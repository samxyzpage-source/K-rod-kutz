# Road to Glory: Kicker — Engine API (as built)

**Status:** generated from the code in `kicker/js/engine/*.js` on the integration pass (INT); every signature below is the
real one (parameter names come from the function definitions, descriptions from their JSDoc). Where the implementation
deviates from SPEC §3.5 on purpose, the deviation is listed in §2 with the reason. UI engineers build against **this**
document; SPEC §3.4 (state schema) and §3.6 (flow table) remain the reference for the data shapes and the screen flow.

Section 3 is generated by `node kicker/test/api_doc.js` (paste its output over §3 whenever a signature changes); sections
1–2 are hand-written. Every exported function also carries JSDoc in the source with its draw order and side effects.

## 1. Conventions

- **One global, classic scripts.** Everything hangs off `window.RTG` (`globalThis.RTG` in Node). Load order (also
  `test/load.js` `ORDER`): `00_namespace, engine/tuning, engine/util, engine/rng, engine/schema, data/blocklist, data/names,
  data/colleges, data/nfl, data/records, data/awards, data/events, data/headlines, engine/names, engine/weather, engine/player,
  engine/kick, engine/schedule, engine/standings, engine/sim, engine/stats, engine/awards, engine/events, engine/contracts,
  engine/draft, engine/season, engine/career, engine/save, engine/api`. Modules resolve each other at call time, so the order
  only matters for `Util`/`Tuning`.
- **`fn(state, rng, args) → result`, mutating `state` in place.** `state` is the `CareerState` of SPEC §3.4; `rng` is an
  `RTG.RNG` instance. Every `RTG.Engine.*` call writes `state.rngState = rng.state()` back before returning, so a save taken
  right after any facade call is exact. Nothing in the engine reads a clock or `Math.random`; `Save.serialize(state, rng, now)`
  takes the time from the caller.
- **The UI only calls `RTG.Engine.*`** (plus read-only helpers: `Kick.model` / `Kick.pMakeAt` for overlays, `Stats.*` read
  helpers, `Standings.topN`, `Season.userGameRef`, `Schema.validate`, `Save.slotSummary`, `Career.stageInfo`,
  `Awards.hofScore`, `Sim.driveLogLine`). Facade functions validate their preconditions and throw descriptive
  `Error('Engine.<fn>: …')` messages — the UI should treat a throw as a programming error, not a game state.
- **`state.pending` drives routing.** Exactly one of:
  - `{kind:'KICKS', session}` — a `KickSession` (`kind` `SHOWCASE` | `CAMP` | `COMBINE_LADDER` | `HALFTIME70` | `TRYOUT` |
    `PRACTICE`; `contexts[]`, `results[]`, `idx`, `rival?`). Play it with `Engine.sessionKick(state, rng, input|null)` once per
    context; the call that plays the last context returns `{done:true, outcome}` (`Career.finishSession` ran) and the pending
    is replaced by whatever comes next (offers decision, camp verdict, …). Combine ladders skip the remaining rungs after a miss
    (`Draft.combineNextIdx`), so read `remaining` rather than counting contexts.
  - `{kind:'DECISION', decision}` — `decision = {kind, payload, options:[{id, label, detail}]}`; resolve with
    `Engine.decide(state, rng, {kind, optionId, extra?})`. Kinds and option ids as built:

    | kind | option ids | payload highlights |
    |---|---|---|
    | `OFFERS_COLLEGE` | offer ids (`payload.offers[i].id`) | `offers[] {id, teamId, teamName, prestige, depth OPEN/VET/STAR, coach TRUSTING/CAUTIOUS/WHISPERER, nil, nearHome, safety}`, `stars`, `walkon`, `myOvr` |
    | `TRANSFER` | offer ids, `STAY` | same offer shape, `mode:'TRANSFER'` |
    | `REDSHIRT` | `REDSHIRT`, `PLAY` | |
    | `DECLARE` | `DECLARE`, `STAY` | `projection {round, low, high, label}` |
    | `COMBINE_PLAN` | `SAFE`, `SHOW` | `pMakeFar` |
    | `UDFA` | offer ids | 2–3 camp invites (`Contracts.generateOffers` `'UDFA'`) |
    | `EXTENSION` | `ACCEPT`, `COUNTER` (extra `{mode:'AAV'|'YEARS'}`), `DECLINE` | `offer, marketAav, satisfaction, counter {aavBump, yearBump, p}` |
    | `FREE_AGENCY` | `OFFER_i`, `OFFER_i_HOME` (hometown discount), `WAIT`, `SIT_OUT` | `offers[], round, marketAav, mode 'FA'|'MIN'` |
    | `TAG`, `CUT_NOTICE`, `BODY_CHECK`, `HOF`, `CAMP`, `OFFSEASON_PLAN` | `OK` (informational) | |
    | `RETIRE` | `ONE_MORE_YEAR`, `RETIRE`, `RING_CHASE` (when the deal is up) | `forced`, `age` |
    | `TRAINING_BLOCKS` | `POW`/`ACC`/`CON`/`CLU`/`KO`, `BANK` | |
  - `{kind:'EVENT', event}` — `event = {id, title, text, sender, choices:[{label, preview}], rolledWeek, rolledYear}`; resolve
    with `Engine.chooseEvent(state, rng, idx)`.
- **Draw counts are documented per function** (JSDoc "Draws:") so replays stay deterministic; `Season.simOtherGames` forks the
  rng per game (`rng.fork('wk<week>:<gameId>')`), so the number of AI games never perturbs the user's own replay.
- **Realm / performance.** In Node the suite loads the engine into a vm context (`test/load.js`); the loader shadows the
  builtins so that realm runs within ~20 % of a browser. Budgets (§2.13, `Tuning.perf`): a full auto season ≈ 70–130 ms, a
  full auto career ≈ 1.1–2 s on the CI box (asserted by `test/perf.test.js`).

### 1.1 The screen flow, as built (SPEC §3.6 with the real calls)

| `stage.phase` | pending | Engine calls |
|---|---|---|
| `HS.SHOWCASE` | `KICKS` (SHOWCASE, 6 contexts) | `Engine.newCareer(opts, now)` created it; `sessionKick` ×6 → outcome `{kind:'SHOWCASE', stars, decision}` |
| `HS.OFFERS` | `DECISION OFFERS_COLLEGE` | `decide` → `COLLEGE.PRE` |
| `COLLEGE/NFL.PRE` | `KICKS` (CAMP) when §2.2 applies, else none | `sessionKick` ×6 (rival kicks are pre-resolved in `session.rival.results`), then `nextPhase` → `.REG` week 1 |
| `.REG` / `.POST` week | none | `train(focus)` once, `spendXp(attr)` any time, `startUserGame` → `simToKick`/`simStep` → on `USER_KICK` `applyUserKick(input)` or `autoKick`; on `USER_KICKOFF` `applyUserKickoff(input|null)`; on `ICE_TIMEOUT` show it and call `simToKick` again (the same kick comes back with `ctx.iced`); on `END_GAME` `finishUserGame` → `GameSummary`; then `endWeek` → `WeekReport`. Bye week (`Season.userGameRef(state) === null`): `train` + `endWeek`. `autoPlayGame` replaces the whole game loop. |
| `.REG` after `endWeek` | `EVENT` (sometimes) | `chooseEvent(idx)`; an event may leave a `KICKS` session (HALFTIME70) or a `DECISION` (mid-season cut → `FREE_AGENCY`) |
| `.AWARDS` | none | `nextPhase` → `.OFF` and the wizard's first decision |
| `.OFF` | `DECISION` chain (`BODY_CHECK` → `TRAINING_BLOCKS` → college `REDSHIRT?`/`TRANSFER?`/events/`DECLARE?`; NFL `CUT_NOTICE?` → `EXTENSION?`/`TAG?`/`FREE_AGENCY?` → `RETIRE?` → 2 events) | `decide` / `chooseEvent` per step (each call resumes the chain); when nothing is pending, `nextPhase` → next `.PRE` (`Season.advanceYear`) or `DRAFT.*` or `RETIRED.LEGACY` |
| `DRAFT.DECLARE` | `DECISION DECLARE` | `decide` (`STAY` → `COLLEGE.PRE`; `DECLARE` → `DRAFT.COMBINE`) |
| `DRAFT.COMBINE` | `DECISION COMBINE_PLAN` → `KICKS` (COMBINE_LADDER, all three parts in one session) | `decide`, `sessionKick` until done, `nextPhase` → `DRAFT.DRAFT` |
| `DRAFT.DRAFT` | none | `nextPhase` runs `Career.runDraft`: drafted → `NFL.PRE`; UDFA band → `DECISION UDFA` (phase `UDFA`); undrafted → `KICKS` TRYOUT |
| `RETIRED.LEGACY` | `DECISION HOF` | `decide` → nothing pending; `Awards.hofScore(state)`, `Stats.careerLine`, `Stats.topMoments`, `Stats.compareToLegends` for the legacy screen |

Result shapes the UI renders (all plain JSON):

- `SimEvent` — `{type:'DRIVE'|'SCORE'|'AI_KICK'|'USER_KICK'|'USER_KICKOFF'|'ICE_TIMEOUT'|'END_QUARTER'|'END_HALF'|'OT_START'|'END_GAME'|'END', text, side?, kick?, ctx?, result?, kickoff?, gs}`.
  After `END_GAME` call `finishUserGame`; `step` after that returns `{type:'END'}` (it does not throw).
- `GameSummary` (`finishUserGame`) — `{gameId, league, week, kind, homeId, awayId, userSide, oppId, score, won, tied, ot,
  userLine:{fga, fgm, pat, patMade, long, gw, tf, pts, made50plus, clutchA, clutchM}, grade, xp:{items[{label, xp}], total, mult},
  meters:{morale, trust, fans, js, fame} (deltas), headline, kicks: KickLogRow[], drives: DriveLogRow[], teamStats, gameWinner,
  tieForcer, played, decisiveMiss, injury, milestones}`. `played === false` means the user did not kick (benched / injured).
- `WeekReport` (`endWeek`) — `{year, week, league, headlines[], messages[], event, eventId, injuries:{active, weeksLeft, cleared,
  isNew}, bench, unbenched, cut, milestones[], award, phaseChange ('POST'|'AWARDS'|null), nextWeek, nextGame, userGame, bye,
  career: {callUp, offers, practiceSquad}}` (+ `decisions[]` from `autoPlayWeek`).
- `DecisionOutcome` (`decide`) — `{kind, optionId, next:'PENDING'|'PHASE', stage, phase, headline, timeline, result}`.
- `EventOutcome` (`chooseEvent`) — `{id, choiceIdx, label, effects, branches[], headline, actions[], session?, actionResults[]}`.
- `KickResult` (`applyUserKick`, `sessionKick().result`) — SPEC §3.4 plus `type, aim, holdMs, overBiasDeg, sigmaDeg, blocked,
  pNeed, auto, forced` and `feedback.missBy.text`.
- `nextPhase` → `{stage, phase, year, week, pending}`.

## 2. Intentional deviations from SPEC §3.5 (and why)

| Module | As built | Why |
|---|---|---|
| `Tuning` | Plain mutable object tree + `RTG.TuningDefaults()`; **not** `Object.freeze`d. `purity.test.js` lints that only `tuning.js` assigns into it. | `RTG.debug.tune` and the balance harnesses replace values at runtime; a deep freeze would force a full copy per tweak. |
| `RNG` | `create(seed)` accepts numbers/strings via `RNG.toSeed`; extra `gaussInt(mu, sd, lo, hi)`. | Seed entry from the UI is text. |
| `Schema` | Extra factories/lookups (`createLeague`, `createAiKicker`, `createRecords`, `setKicker`, `teamIn`, `teamById`, `userTeam`, `activeLeague`, `phasesFor`, `emptySeason`, …); `league.kickers` is an enumerable cache of the same objects as `team.kicker` (stripped by `Save`, relinked by `reindex`); `teamIndex` is non-enumerable. Teams/players carry a few extra fields (`coach`, `region`, `rival`, `bigMarket`, `gamesPlayed`); `validate` tolerates unknown keys. | Needed by the sibling modules; JSON round-trip equality still holds. |
| `Names` | Extra `nickname(rng, city)`; draw counts fixed at player 3 (+1), coach 1, reporter 3, hometown 1. | Documented so replays are exact. |
| `Weather` | `forGame` also returns `climate` and `month`; domes consume 0 draws. | Sim/Events read them. |
| `Player` | `spendXp(player, attr, opts?{focus})` (3rd arg); `updateJobSecurity(state, summary|null)` accepts a bye and returns `{js, benched, cutWarning, delta, lowWeeks}`; extra `applyStars`, `applyGameResultMeters`, `kickCounts`, `rivalOvr`, `marketMult`, `trainingXp`, `injuryProb`, `careerThreatProb`, `formText`. Career-threat injuries follow the §2.4 difficulty table (not the §2.1.4 sentence). | The focus discount has to reach `Player.spendXp` through the facade; §2.1.4 vs §2.4 contradiction resolved toward the table. |
| `Kick` | `buildContext(state, gs|null, situation, [rng])` — the rng is the 4th argument (or `situation.rng`); without one a deterministic fallback keyed on `state.rngState` is used and the caller's rng never advances. `aiInput(rng, ctx, attrs, [model])` — `model` optional (`Kick.geometry` suffices). `resolve` returns extra fields (see §1.1). Trait σ effects are folded into the mods factor. | §3.5.8 lists the draws but no rng parameter; Sim must pass the game rng so hash/wind draws are replayable. |
| `Schedule` | Extra `teamGames`, `gameFor`, `findGame`, `validate`. NFL rotation cycles the three perfect matchings of the four divisions by `year mod 3` (the spec's `(year + divIdx) mod 3` is not a symmetric pairing). | Correctness. |
| `Standings` | `compute(season, league, [rng])`, `conferenceChampionshipGames/playoffField/bowls/nflPlayoffField(season, league, [rng])`, `advanceBracket(bracket, results, [league])`, `draftOrder(season, league, [rng])`; pure (they do not write `season.*`) plus one explicit mutator `recordResult(season, league, game)`; `rankings` ranks all 48 (slice with `topN`). | One writer for `season.results` keeps the h2h format consistent between Sim, Season and fixtures. |
| `Sim` | `startGame(state, rng, gameRef, [opts{ai}])`; `step` returns `{type:'END'}` forever after `END_GAME` instead of throwing; `applyKick`/`applyKickoff` return the resulting `SimEvent` (spec: void); gameWinner/tieForcer tags are resolved in `finishGame` (two-phase). | Safer UI loop; the tags need the final score. |
| `Stats` | `recordKick` returns `null` for kickoffs (no log row; KO counters only); `checkRecords(state, ctx?, result?, opts?{final})`; extra `applyKick`, `momentScore`, `emptyStats`, `ensureStats`, `BUCKETS`. | A KickoffResult has no §3.4 outcome enum. |
| `Awards` | Extra `kickerScore`, `candidates`; season goals are returned by `compute` as `goal:true` entries but not stored in `history.awards`; `hofScore` uses NFL-only inputs and a deterministic induction year. | Keeps the trophy case clean; the §2.7.9 worked example only reconciles with NFL inputs. |
| `Events` | `message(state, kind, vars)` picks deterministically (fnv1a of kind/year/week/seq — no rng, per the signature); extras `weeklyTick`, `halftimeSession`, `resolveHalftime70`, `eligible`, `slots`, `force`, `CAREER_FLAGS`. HALFTIME70 is consumed inside `apply` (it becomes a `KICKS` pending, not an action). | §3.5.18 `handleActions` enumerates no HALFTIME70 action. |
| `Contracts` | `marketValue(state, opts?)` returns the multipliers too; `generateOffers(state, rng, mode, opts?)`; `counter(state, rng, decision, mode?)` (one draw covers accept / stands / withdraw); `cutCheck` is a pure check and `applyCut(state, reason)` performs it; `sign(state, offer, rng?)` moves the player through `Career.changeTeam` when an rng is given; `waitRound`, `offerFor`, `extensionEligible`, `tagEligible`, `aavFor`, `ageMul/fameMul/marketMul/gtdPct` are extra. AAV base/per rescaled ÷0.92 so the §2.7.7 worked values hold at fame 0. | Spec formula vs worked values. |
| `Draft` | `combineSession(state, rng, opts?{part, plan})` returns ONE session (kind `COMBINE_LADDER`, `parts:{ladder, acc, ko}`) holding all three mini-events; `run` returns the rookie `contract` and does **not** sign/move the player (`Career.runDraft`/`enterNfl` do); extras `combineNextIdx`, `combineBreakdown`, `roundFor`, `roundLabel`, `draftOrder`, `scoreTryout`. | One session = one UI flow; signing belongs to Career. |
| `Season` | `endWeek` throws on: a pending, a game in progress, the user's game unplayed, out of season; extra `simUserGameAuto`, `ageTick` (idempotent per year — the Body Check card previews it); week 13 (college CCG week) counts as the last REG week; `Contracts.payoutSeason` is called by `Career.offseasonChain`, not by Season. | Facade contract; §2.7.3 "REG weeks 1–13". |
| `Career` | `showcaseSession` does not set `state.pending` (`Schema.createCareer` wraps it); `retire(state, rng, reason?)`; `enterNfl(state, rng, teamId, contract?, opts?)`; extras `resume`, `afterWeek`, `eligibility`, `forcedRetirement`, `starsFor`, `runDraft`, `DECISION_KINDS`, `ACTIONS`. Stars = `clamp(round(1.5 + 0.03·(OVR − 40) + 0.4·makes), 2, 5)` (per make, not per make/6). College offseason events roll before `DECLARE`. Extra decision kinds `BODY_CHECK`, `CAMP`. | The literal §2.7.1 formula makes every recruit a 2★ walk-on. |
| `Save` | `deserialize` also accepts the JSON string; the blob packs row arrays and KickerStats blocks (`{_cols,_rows,_miss,_sub}`, `{_ks,_b}`, `career._pack`) — lossless, key order aside; extras `checksum`, `stripCaches`, `packRows/unpackRows`, `packStats/unpackStats`, `toBase64/fromBase64`, `byteSize`. | A real 20-season career was 455 KB unpacked; packed it is ≈ 320–340 KB (< 400 KB). |
| `Engine` | `applyUserKick(state, rng, input, opts?)` and `sessionKick(state, rng, input, opts?)` accept `opts.forced = {outcome, sub?, side?}` (debug: the requested outcome, no input needed, zero rng draws — `RTG.debug.forceKick` uses it). `applyUserKick` = `Kick.resolve` + `Sim.applyKick` only (Sim already records the row and applies the meters — calling `Stats.recordKick` again would double count). `nextPhase` returns `{stage, phase, year, week, pending}` and throws in REG/POST. Extras `settlePending` (with `opts.max` to step a chain one pending at a time), `markRead` (the inbox read flag, dispatchable so the UI never writes state directly), `autoOption`, `autoSpend`; `autoPlayOffseason(opts.untilStage)`, `autoPlayCareer(opts.onSeason)`. Default auto policies: declare as soon as eligible; retire from 32 unless OVR ≥ 88, hard stop 35 (the spec's "stay until projected round ≤ 4" never triggers with the §2.7.6 draft value, and "retire when forced" would end every career at 42). | See `Tuning.career.autoplay`. |
